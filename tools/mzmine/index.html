GC-EI-MS processing and annotation with MZmine

The GC-MS procedure in the MZmine Nature Protocols workflow converts GC-EI-MS data into deconvoluted component spectra and aligned quantitative features. These outputs can be annotated against EI spectral libraries and exported for downstream analysis or GNPS-compatible GC-MS workflows.

  1. Import GC-EI-MS data

    Load supported GC-MS data and configure mass detection and chromatogram construction for electron-ionization spectra.

  2. Detect chromatographic signals

    Build ion chromatograms and detect chromatographic peaks using settings appropriate to peak width, signal-to-noise, and the GC method.

  3. Deconvolute EI mass spectra

    Resolve overlapping chromatographic signals into representative component spectra using a spectral-deconvolution workflow.

  4. Align components across samples

    Align deconvoluted features/spectra across the sample set and apply appropriate quality filters.

  5. Annotate and export

    Match deconvoluted EI spectra against suitable spectral libraries and export quantitative tables and representative spectra for downstream analysis.

Requirements

  • GC-EI-MS data of sufficient chromatographic resolution and signal quality for deconvolution.

Considerations

  • Deconvolution quality strongly affects downstream spectral-library matching; chromatographic and spectral parameters should be tuned to the instrument and sample complexity.
  • The published procedure targets MZmine 3; current MZmine 4 documentation should be used to map the procedure onto current modules.

Heuckeroth S, Damiani T, Smirnov A, et al. Reproducible mass spectrometry data processing and compound annotation in MZmine 3. Nature Protocols 19, 2597–2641 (2024).

MS-imaging processing and annotation with MZmine

The imaging procedure in the MZmine Nature Protocols workflow processes spatially resolved MS or IMS-MS data into features that can be visualized as ion images and linked to spectral/annotation evidence. The workflow is applicable to imaging modalities supported by MZmine and can integrate ion mobility where available.

  1. Import spatial MS data

    Import supported imaging data while preserving spatial coordinates and, where available, ion-mobility information.

  2. Detect and organize imaging features

    Apply mass detection and feature-processing steps appropriate to the imaging acquisition to generate spatially resolved ion features.

  3. Visualize spatial distributions

    Inspect ion images and, where available, mobility or spectral dimensions to assess localization and data quality.

  4. Annotate spatial features

    Use available MS/MS, spectral libraries, lipid annotation, or other MZmine annotation modules to add chemical context to spatially resolved features.

  5. Export reproducible results

    Save processing configurations, feature information, images, and compatible outputs for downstream statistical or annotation workflows.

Requirements

  • Imaging-MS data in a format supported by MZmine; ion-mobility information is optional and instrument dependent.

Considerations

  • Spatial resolution, normalization, matrix/background effects, and annotation confidence require imaging-specific quality assessment beyond generic LC-MS preprocessing.
  • The published procedure targets MZmine 3; consult current MZmine 4 imaging documentation for current module names and supported acquisition types.

Heuckeroth S, Damiani T, Smirnov A, et al. Reproducible mass spectrometry data processing and compound annotation in MZmine 3. Nature Protocols 19, 2597–2641 (2024).

Untargeted LC-(IMS)-MS processing and annotation with MZmine

This strategy captures the LC-(IMS)-MS procedure published for MZmine 3: raw spectral data are converted into aligned quantitative features linked to isotope patterns, ion mobility where present, and MS/MS spectra, then annotated and exported for downstream tools. Current MZmine 4 uses the same broad processing logic while providing updated modules and wizard-driven workflows.

  1. Import and inspect LC-MS or LC-IMS-MS data

    Import supported vendor/open data, apply appropriate mass detection, and inspect chromatographic and spectral quality before feature processing.

  2. Build chromatograms and resolve features

    Construct extracted-ion chromatograms and resolve chromatographic peaks using experiment-appropriate intensity, mass-tolerance, retention-time, and peak-shape settings.

  3. Group isotopes/ions and align samples

    Group isotopic and related ion signals, align features across samples, perform gap filling where justified, and apply blank/QC or other quality filters.

  4. Annotate features

    Use spectral-library matching, local databases, lipid annotation, and ion-identity relationships as appropriate to generate feature annotations.

  5. Export to downstream annotation/networking tools

    Export aligned feature tables and spectra for GNPS FBMN/IIMN, SIRIUS, MetaboAnalyst, or other downstream analyses while retaining the MZmine batch configuration for reproducibility.

Requirements

  • Appropriate raw/open MS data and experiment-specific processing parameters; DDA MS/MS is especially useful for feature annotation.

Considerations

  • The published procedure targets MZmine 3 and should be adapted using current MZmine 4 documentation and wizard defaults rather than copied blindly.
  • Batch files and software version should be retained and reported to support reproducibility.

Heuckeroth S, Damiani T, Smirnov A, et al. Reproducible mass spectrometry data processing and compound annotation in MZmine 3. Nature Protocols 19, 2597–2641 (2024).

Overview

MZmine is a modular mass-spectrometry processing environment with graphical, batch, wizard-guided, and command-line workflows. Current MZmine supports LC-MS/MS DDA and DIA, LC-IMS-MS, GC-EI/CI-MS, direct-infusion and imaging workflows; feature detection, resolving, alignment and filtering; ion/isotope/adduct grouping; spectral-library and lipid annotation; interactive molecular networking using classical/modified cosine and learned spectral-similarity models; statistics and fragmentation dashboards; and direct exports/integrations with GNPS, SIRIUS, MetaboAnalyst, and other downstream resources.

Common uses

  • Process untargeted LC-MS/MS DDA/DIA and LC-IMS-MS data from raw files through aligned feature tables and annotations.
  • Perform GC-EI/CI-MS spectral deconvolution, MS-imaging processing, direct-infusion analyses, and specialized lipidomics workflows.
  • Run interactive molecular/ion-identity networking locally using spectral similarity and machine-learning similarity models.
  • Perform spectral-library and rule-based lipid annotation, interactive statistics/fragmentation review, and exports to GNPS, SIRIUS, and downstream analysis tools.
  • Generate and curate reference spectral-library data using batch/wizard-assisted processing.
  • Inspect aligned features and associated spectra before exporting to GNPS, SIRIUS or statistical analysis.

Scope and considerations

Designed for

  • Modular processing and inspection of untargeted LC-MS and LC-IMS-MS datasets, including feature-based workflows that retain links to MS/MS and ion-mobility information.
  • GC-EI-MS spectral deconvolution and alignment, MS-imaging workflows, and interactive or batch processing with exports to downstream annotation and molecular-networking resources.

Not designed for

  • A replacement for every downstream structure-elucidation or statistical-analysis platform; specialist tools are commonly used after preprocessing.

Important requirements

  • Desktop installation; stable releases provide Windows, macOS, and Linux packages and include the required Java runtime.

Considerations

  • Parameter choices for feature detection, resolving, alignment, normalization, networking, and filtering remain experiment dependent and should be preserved in batch files or wizard configurations.
  • The 2024 Nature Protocols procedures were published for MZmine 3; current MZmine 4 workflows preserve core concepts but interfaces, licensing, and available modules continue to evolve, so current documentation should be consulted.
  • MZmine Community is available through an academic program, while current project pages also advertise enterprise/commercial packages; users should verify current licensing for their setting.
  • Retain the raw-data links and batch configuration with feature-table and MS/MS exports; downstream tools need matching feature identifiers.
